# M8.2 WPT smoke

M8.2 adds the first upstream Web Platform Tests smoke lane to Openbrowser's compatibility system.

## Scope

The workflow pins an exact `web-platform-tests/wpt` commit and runs a deliberately small testharness subset against the same Chromium 151 line used as the M8.1 compatibility reference.

Initial smoke areas:

- DOM element creation;
- Encoding API basics;
- UTF-16 surrogate handling in TextEncoder/TextDecoder;
- URLSearchParams construction and lookup;
- Web Storage `setItem` semantics;
- Web Storage key enumeration.

The exact paths are versioned in `tests/wpt/smoke-tests.txt`.

## Reproducibility

- WPT revision: `3a1177e6c76f1a7f854f3ae4b93a00835e171fad`;
- Chrome for Testing version: `151.0.7922.138`;
- ChromeDriver version: `151.0.7922.138`;
- the workflow verifies the checked-out WPT commit and browser/driver runtime versions;
- machine-readable `wptreport` output and run metadata are uploaded as CI artifacts.

The first CI execution records SHA-256 values for the Chrome and ChromeDriver archives. Those hashes must be pinned in-repository before this PR is considered merge-ready.

## Execution contract

The PR smoke is intentionally strict:

1. the WPT checkout must resolve to the repository-pinned commit exactly;
2. Chrome and ChromeDriver must both report the expected `151.0.7922.138` version;
3. after the bootstrap run, both download archives must match repository-pinned SHA-256 values before extraction;
4. the smoke manifest must contain at least one explicit test path;
5. `wptrunner` must produce a machine-readable `wptreport` artifact;
6. unexpected WPT failures remain job failures and are not hidden by broad expectations or `--no-fail-on-unexpected`;
7. infrastructure/setup failures are distinct from standards-test failures and must be fixed rather than reclassified as passes.

This contract makes the WPT lane reproducible evidence instead of a moving upstream smoke check.

## Current boundary

This first WPT slice establishes the standards-test ingestion, pinning, reporting and CI boundary. It does **not** claim direct Openbrowser execution through `wptrunner` yet because Openbrowser does not currently expose a WebDriver-compatible product adapter.

M8.1 remains the layer that executes Openbrowser itself against the pinned Chromium reference on deterministic scenarios. Future work can add an Openbrowser `wptrunner` product/automation adapter without changing the pinned WPT corpus or reporting boundary introduced here.

## Gate

A WPT smoke failure is a real signal and must not be converted into a pass by broad expectations or `--no-fail-on-unexpected`. If an upstream test is unsuitable for the PR smoke subset, remove or replace it with a documented reason rather than silently accepting an unexpected failure.
